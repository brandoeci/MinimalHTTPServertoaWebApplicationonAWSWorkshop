6. THE SEQUENTIAL LIMITATION (section 6.2)
==========================================================
Two clients ask at the same time: A calls the slow service, B calls /app/time
right after. B has to wait until A finishes, even though both were launched
within the same 200 ms.

A  GET /app/slow?millis=5000 -> HTTP 200  started at +0.0s  total 5.003185s
B  GET /app/time            -> HTTP 200  started at +0.3s  total 4.673475s

B normally answers in a few milliseconds (see section 2). Here it took about
as long as A was still sleeping: the accept loop could not take B until A was
done. The browser stayed responsive, but the server did not become concurrent.
